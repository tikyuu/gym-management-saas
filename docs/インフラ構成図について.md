# インフラ構成図について

[インフラ構成図.drawio](インフラ構成図.drawio)を、VS CodeのDraw.io Integrationまたはdiagrams.netで開く。アイコン、文字、枠、接続線を個別に編集できる。

## 図の目的と構成

詳細な設定値ではなく、AWSサービスの配置と通信・連携の関係を把握するための図。

1. **本番環境・通信経路**：ブラウザ、DNS、CloudFront・WAF、S3、Cognito、VPC Origin、ALB、ECS、RDS、外向き通信。
2. **管理・運用の関係**：アカウント分離、CI/CD、ECR、Secrets Manager、CloudWatch、SES、ACM。

CIDR、ポート番号、リソース容量、保持期間、ルール閾値は図へ掲載せず、[インフラ基本設計書](インフラ基本設計書.md)と[要件定義書](要件定義書.md)で管理する。設計書の基準コミットは `40662c3`。本図は設計構成であり、デプロイ済みの状態を示すものではない。

## 読み方

- Route 53はDNS名前解決を担当する。HTTP通信の中継装置ではない。
- Cognitoは必要な操作時にブラウザが直接利用する。通常のAPI通信はCloudFrontからALBへ進む。
- 2つのALBアイコンは、同じ1つのALBの両AZ配置。両AZの正常なTaskへ転送でき、矢印は代表経路を示す。
- RDSのStandbyは待機系であり、通常の読み取り先ではない。
- NATとS3 Gateway Endpointは両AZから利用する。図では代表として片側のTaskから矢印を引いている。EndpointはECRイメージレイヤー等の取得用で、React配信用S3へのアクセス権限を意味しない。
- IGWはVPCへ接続する。CloudFrontからVPC Origin・ALBへの通信経路には使用しない。
- 2ページ目は論理的な操作・データの流れ。ネットワーク経路は省略している。ACMは証明書管理であり、通信を中継しない。

## 後続設計で確認する事項

- DNS配置アカウント・ゾーン委任。主図のRoute 53は論理配置。
- 3つのCognito User Poolそれぞれのドメイン。開発用ドメインはDNS章とCognito章で方針が異なるため統一する。
- ALB証明書とオリジン名・Hostの整合、API転送パス、WAFルール・レート閾値。
- 通知手段など、監視・ログ設計の具体化。
